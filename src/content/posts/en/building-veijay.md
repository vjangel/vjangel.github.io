The previous version of VeiJay was generated by Hexo. Its publishing repository held the resulting HTML, stylesheets, and scripts. The Astro 7 rebuild keeps the page components, Markdown, and build configuration in the repository. The homepage brings projects and technical notes together, with a listing and detail pages for each. Titles, descriptions, and dates live alongside the content, so the homepage and listings can read them at build time.

## Chinese and English content

Chinese pages use the root paths, and English pages live under `/en/`. Each language has its own Markdown file. Matching filenames identify the same project or note, so switching languages on a detail page keeps readers on that item. When a translation is missing, the page displays the available text and marks its language. The homepage and footer share the same social link configuration. GitHub is the only link currently displayed, and platforms with empty URLs are hidden.

## The interactive homepage

Translucent panels sit over a Canvas background. Moving the pointer bends the light ribbons and leaves a trail. Clicking an open area sends out a ripple. The canvas reuses glow textures prepared at startup and sits behind the content, where it leaves navigation and project links clickable. The homepage has a motion toggle and follows the system's reduced-motion preference on the first visit. Drawing pauses when the tab moves to the background. Project details and notes use a static background.

## Building and publishing

On a fresh setup, Node.js 24 and `npm ci` install the versions recorded in the lockfile. Running `npm run build` generates the static site in `dist/`, and `npm run preview` serves that output locally for review. The previous site's published files are still available in Git history.

The GitHub Actions workflow is configured to check builds for pull requests to `main`, then upload `dist/` and deploy it to GitHub Pages when `main` is updated. At the time of writing, the new site had been built and previewed locally. The workflow had yet to run on GitHub. The first release requires switching the Pages source to GitHub Actions.
